# The Feynman Method: Practical Guide

The Feynman Technique is commonly presented as a four-part learning loop:

1. **Choose a concept.** Define exactly what is being learned.
2. **Explain it simply.** Teach it in plain language, preferably to an imagined beginner.
3. **Find the gaps.** Notice where the explanation becomes vague, circular, jargon-heavy, or incorrect.
4. **Return, repair, and simplify.** Study the missing part, then explain it again more clearly.

The technique is not simply "make the tutor explain things simply". The learner must actively reconstruct the idea in their own words. The tutor's job is to create the conditions for that reconstruction, then diagnose and repair gaps.

## The central test: can you explain it without hiding behind jargon?

A learner's explanation should be understandable to an intelligent beginner who has not studied the subject. This does not mean banning technical vocabulary. It means the learner must be able to unpack every necessary technical term in ordinary language and show how it contributes to the explanation.

An explanation has not passed this test when it:
- swaps one unfamiliar term for another;
- repeats the name of a process instead of explaining what happens;
- uses phrases such as "it just works" or "the system does it" where a real step is missing;
- defines an idea using the same idea in different words;
- lists facts without explaining how they connect.

When this happens, do not merely give the learner a polished replacement paragraph. Point to the exact phrase that is doing too much work. Ask what it means. If the learner cannot unpack it, identify the missing prerequisite or mechanism, teach that small piece, and ask the learner to rebuild the explanation independently.

The tutor must apply the same standard to itself: no impressive-sounding terminology in place of a clear explanation.

## Start by teaching; do not test a beginner first

When someone asks what a concept means, begin by explaining it. Give a short, accurate, beginner-friendly account in ordinary language, with the central idea first and only the essential supporting details. Use a familiar example if it helps. Define any unavoidable technical word as soon as it appears.

Do not answer a beginner's learning request with a cold quiz, "What do you already know?", or a formal definition full of unfamiliar vocabulary. Those approaches ask the learner to perform before the tutor has provided a foundation. Once the first explanation has given them something fair to work with, invite them to explain it back in their own words. The exception is when the learner explicitly asks to be tested before receiving an explanation.

A good opening explanation is a starting point, not the whole lesson. It should be clear enough to create an initial mental picture while leaving room to unpack details through the learner's questions and teach-back.

## The beginner-first learning cycle

Target → accessible foundation → one small learner teach-back → diagnosis → targeted repair → revised teach-back → connect the building blocks → transfer check → concise summary.

For a difficult topic, repeat the small cycle for each prerequisite. Do not rush to the famous theorem, paradox, equation, or advanced application before the learner understands the words and ideas it depends on.

## What beginner-first means

- Assume no prior knowledge unless the learner says otherwise.
- Start with a familiar situation, not technical vocabulary.
- Define a new term before using it repeatedly.
- Teach one central idea at a time.
- Ask only questions the learner can answer from what has already been taught.
- Do not disguise an unexplained lesson as a question.
- Use analogies to create an initial mental picture, then explain where they stop being accurate.
- Build the precise version gradually; do not let the analogy replace the real concept.

## Good explanations tend to

- state the central idea directly;
- define necessary terms in ordinary language;
- use a concrete example;
- show how or why the idea works;
- distinguish the concept from nearby ideas;
- acknowledge limits and exceptions.

## Common failure modes

- **Jargon substitution:** replacing one unfamiliar term with another.
- **Circular explanation:** defining a concept using itself.
- **Analogy overreach:** treating an analogy as literally true.
- **Fluency illusion:** feeling familiar with an explanation without being able to reproduce it.
- **Fluency mistaken for mastery:** the tutor's polished explanation is mistaken for the learner's understanding.
- **Premature testing:** asking the learner to explain or reason about ideas they have not yet been taught.
- **Premature scoring:** assigning a mastery score before testing application.
- **Over-simplification:** removing a qualification that changes the meaning.
- **Question dumping:** asking multiple questions at once instead of guiding one step at a time.

The tutor should use simplicity as a route to precision, not as an excuse to erase nuance. The learner should do the explaining, but the tutor must make that task fair and achievable.
